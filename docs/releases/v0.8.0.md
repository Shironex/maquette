# v0.8.0: Animation recipes, a stricter ship gate and built assets in place of models

The seventh update after the public release, and the largest so far. The big addition is animation
recipes: change a clip without redrawing it (a hand reaching a prop, a lean, pinned feet, keyed
poses, a sword grip, clips joined into one), preview it, bake it exactly in headless Blender, review
the numbers and add it as the model's next version. Around it, a website run an agent starts now
always stops before Ship when an agent chose the repo or its folders, a built asset can take the
place of a generated model in one undoable step, agents can render any model from standard angles in
the page's own light, sends are numbered per project, and the rig doctor learned to bind wings
rigidly. Most of it was tried with automated tests, real headless Blender runs, mock mode and visual
checks per change. The first recipe slices were also tried by hand in the real app, which is where
the fixes listed below came from. The Known limits section says what I did not run by hand. It is
still early: back up your workspace before you update.

## Highlights

- **Animation recipes:** a Recipes tab in the Motion view to edit a base clip or the rest pose with
  reach, nudge, look at and wave, a rough preview, an exact headless Blender bake, a review with pass
  or warn numbers, and Add as vN.
- **Recipes round 2:** joined clips with blends, trims, retimes, freezes, holds and mirror on one
  timeline, pinned feet and hands, pose keys with a turn gizmo, grip presets from a workspace grip
  library, and seam checks with fixes ordered best first.
- **A recipe library** across projects, with revisions, Use in project, Save back after a diff,
  import and export, and nine built in starters.
- **Stricter ship gate:** a website run an agent starts stops before Ship, whatever Ask before
  shipping says, when an agent chose the repo it writes into or the site folders inside it.
- **Built asset in place of a model:** Replace with a built asset on the Board puts a script made
  model where a generated one stood, keeping the asset's place in the layout, and Bring back the old
  model undoes it.
- **Render views and model facts:** agents get standard pictures of any model, lit the way the page
  lights it, and its size, facing and counts without writing a script.
- **Built asset helpers:** a helper module with 26 functions and an example script land in `built/`
  in every project.
- **Sends numbered per project,** with the project in the By hand export name.
- **Rig doctor:** rigid parts (wings, a cape, a braid), a better facing read for upright characters,
  and an Inbox warning for a walk that travels against the face.
- **MCP tools from 134 to 156,** and two new agent skills in plugin 0.6.0.

## What's new

### Animation recipes

A recipe changes an animation without touching its keys. It is one small file,
`recipes/<id>.recipe.json`, that names a base clip (or the model's rest pose), the blanks each
project fills in (a prop or a point) and the changes, on humanoid bone names. It never holds keys,
frames, a mesh, a skeleton or a render, so it is small, it can be shared, and it works on any
humanoid model. On another computer the base clip is found again in the clip library by name and
frame count. The whole path is in the new
[Animation recipes guide](https://shironex.github.io/maquette/docs/guides/animation-recipes/).

- **Recipes tab** in the Motion view, with New recipe from a library clip or from the Rest pose
  (60 frames at 30 fps by default, 2 to 600).
- **Editor.** Changes of four kinds (reach, nudge, look at, wave), each with a bone, its settings and a
  range on the timeline, and blanks with a prop picker or a point. Problems show inline with the same
  checks the core runs. Unsaved edits survive a change of tab or view, leaving asks Save, Stay or Leave
  without saving, and quitting offers to save. An agent's write to the open recipe merges by id, and
  only a real clash asks Keep mine or Use theirs.
- **Rough preview.** The model plays the recipe in three.js with markers for the blanks, and lists a
  hand that ends more than 2 cm from its target or an elbow that flips. It is labelled as rough: the
  bake solves it exactly.
- **Exact bake.** Apply bakes the recipe onto the model in one headless Blender run, with progress and
  Cancel, into a staged model with one new clip in the cache. Nothing reaches the project yet.
- **Review and add.** The review plays the baked clip beside the base clip and shows each number as
  pass or warn: hand or foot gap (2 cm), elbow or knee flip, foot slide and rig stretch against the
  base clip's own. **Add as vN** lands it as the model's next version. Baking again replaces that
  recipe's own older clip instead of piling up copies.
- **Mixamo.** A bake of a Mixamo base clip stays in the cache and never enters the clip library or an
  export pack. A record in `recipe-bakes.json` keeps that flag through later Blender steps.
- **Out of date.** A bake reads as out of date when the recipe's motion, its base clip or the model's
  newest version changed since, and the review offers Bake again.

### Recipes round 2: joins, pins, pose keys and grips

The recipe file gains a version 2 for the new parts. A recipe is still saved as version 1 until it
uses one of them, and goes back to version 1 when they are removed, so v1 files load and save byte
for byte.

- **Joined clips and base edits.** Up to 8 clips in one recipe, each with a trim and a blend window
  (8 frames by default, hips and facing lined up), plus mirror and time edits: retime a range, freeze
  a frame, hold over. One timeline in the core drives both the Blender bake and the preview, and
  changes stay on the motion they were placed on when clips are joined, moved or taken out.
- **Pins.** Feet and hands held to a spot, solved last in the bake, after every other change. A foot
  can keep flat. The review adds a Pin drift line per pin (1 cm).
- **Pose keys.** A turn gizmo with Local and World rings, a body map and bone list, key lanes per bone
  (drag moves, Alt drag copies), five eases, Add or Replace layers with a weight, Copy, Paste, Mirror
  and shortcuts. A table of humanoid joint limits warns on a keyed turn past a limit, and the review
  adds a Joint limits line.
- **Grips.** Hand poses kept in a workspace grip library (`library/grips/`), grouped by weapon, for
  the right, left or both hands. Add a grip opens a picker of schematic hand pictures, a recipe keeps
  its own copy with a link back and offers Update to rN when the library has a newer one, and Save a
  grip makes one from your pose keys. Grips bake, and a two handed grip gets a Grip hand gap line
  (2 cm).
- **Seam checks.** The review measures where clips meet and where holds ease (Seam pop and Hold seam,
  at 2 cm or 25 degrees) and flags side bones a mirror cannot pair. A pose sheet shows stills at the
  frames worth a look, and Fixes lists changes best first (a wider blend, a longer ease, a smaller key
  turn) with what the number should come to. Try it lays a fix on the recipe unsaved and opens the
  editor.
- **Agent drafts.** What an agent changes shows as drafted, under the agent's name, until you save:
  a banner, a drafted tag on each change and blue keys in the lanes. The write is in the file at
  once; the marks live beside it in `recipes/<id>.drafts.json` and never travel with an export.

### Recipe library and starters

- **Library on disk** at `library/recipes/<id>/`, one file per revision. A revision never changes once
  written, and a revision number is never reused.
- **Use in project** copies a revision in. A prop blank whose asset the project lacks opens with a
  note, and a missing base clip still makes the recipe, with a note.
- **Save back** shows a plain word diff against the latest revision and writes the next one only. It
  refuses when the entry changed since the sheet read it, or when nothing changed.
- **Import and export** of one `.recipe.json`, checked whole before anything is written (32 changes,
  16 blanks, 256 KB). An export carries no absolute path and no library link. A taken name becomes
  `Name (2)`.
- **Nine starters**, read only in Animations > Recipes: Wave hello, Look at a point, Reach for a prop,
  Lean in and Point while walking, plus a slash combo and a scythe charge, each with a left handed
  copy. Starters name their clips (for example Idle or Walk) and say when the clip library lacks one.
- Animations gains **Show > Recipes** and a **Grips** part with revisions and removals, each with a
  confirm.

### A stricter ship gate for agents

- A website run an agent starts now stops before Ship when an agent chose the repo it ships into:
  the run's own `repo`, or a site repo an agent set that you have not replaced in the app since.
  Before, with Ask before shipping off, such a run shipped with no card.
- The same holds when an agent set the site folders of that repo (models folder, posters folder or
  data file, through `set_ship_settings` from any project on the repo), until you save the folders in
  the Ship view. The Ship view says so under the folders.
- While a run into a repo is queued, going or waiting on its card, its folders cannot be changed
  from any project, so the folders the card names are the ones Ship writes to. An agent's data file
  that names another file already in the site is refused.
- The Ship approval card names the repo with its folders, and the step's waiting line says why it
  waits. A repo you set yourself still ships unasked with the setting off, and your own runs from the
  app are as before.

### A built asset in place of a model

When a script builds a cleaner version of a model that already stands in the scene, **Use in place
of a model** on the built card (or **Replace with a built asset** on the model's own card) swaps it
in. The old asset keeps its id and becomes the built one, so the layout, camera stops and ship data
never change, and the next run builds, bakes and ships the built model.

- A sheet shows both models side by side (triangles, bytes, bounds, real size) and what happens to
  every setting: the real size carries over, fix-ups and switches recorded for the old model give way
  to the built asset's own, part names carry where the new model has that part, and anything the new
  model cannot resolve is reported, never dropped. Nothing is aligned.
- **Bring back the old model** undoes it: the built card comes back from the trash and the versions
  added since go to the workspace trash with a note. Nothing is deleted.
- Until a run ships the swap, the Ship view, `get_ship_plan` and the Ship approval card name it with
  both files.
- Agents use `replace_with_built_asset` (with `dryRun` and `undo`). An agent cannot undo while a
  version that would leave did not come from the script; you can, on the Board.

### Built asset helpers

- `built/maquette_helpers.py` ships with 26 helpers for built asset scripts (materials, shapes,
  outlines, crisp edges, bevels, booleans, join, origin and ground) and `built/maquette_example.py`
  builds a desk set that calls each one once. Both land in every project, and the starter banner
  offers them to an older project.
- A script imports it as `import maquette_helpers as mq` and lists `built/maquette_helpers.py` among
  its helpers, so updating the helper file marks exactly the assets that use it.
- A new [Built assets guide](https://shironex.github.io/maquette/docs/guides/built-assets/) lists
  every helper.

### Render views, model facts and the page light

- **The page light.** One preview rig lights the way the starter pipeline bakes light and the site
  scene shows it (three.js ACES Filmic at exposure 1.15). A built asset's thumbnail now uses it, so
  pale colours no longer clip to white. On fifteen swatches the mean colour difference against the
  page fell from 24.8 to 2.3. Other thumbnails keep the studio look. A new docs page, The page light,
  has the numbers.
- **`render_views`** renders any model as a three quarter view, front, top down and two close ups
  (1024 px), plus one sheet of every picture after the asset's refs, and can put two versions side
  by side with the same cameras.
- **`get_model_facts`** answers counts, the box, the real size, the facing with how sure it is, the
  layout entry and the refs, without running Blender.

### Sends numbered per project

- A send's id is now numbered in its own project, so the first send of an asset in a new project is
  number 1, whatever other projects sent. The By hand export name carries the project:
  `maq_<project>_<asset>_v<n>_<provider>`.
- A send from before this version keeps waiting for the name on its card, so a file saved under it
  still lands.
- `get_provider_job` and `cancel_provider_jobs` take `project`. An id that is a send in several
  projects, given alone, answers `job-in-several-projects` with the projects.

### Rig doctor and Inbox

- **Rigid parts.** Wings, a cape or a braid that an auto rig weighted to the arm bones can be bound
  rigidly to one body bone (Spine2 by default). The doctor lists them under Parts on the arm bones,
  the bind runs on a copy of the draft with a pose test before and after, and Use bound parts, Keep
  the fix's weights and Undo the bind decide it. A bind and a joint move cannot both be in the draft,
  and each card says why.
- **Facing.** On an upright two legged character the front now comes from the feet and the head is
  the chain that reaches highest. A character facing +X used to read as +Z.
- **Walk against the face.** A new Inbox row warns when a walk, run, jog or sprint clip travels more
  than 120 degrees away from the way the model faces. Backward walks are left out.

## Agents and MCP

**MCP tools went from 134 to 156.**

- **Recipes (15):** `list_recipes`, `get_recipe`, `create_recipe`, `update_recipe`, `bake_recipe`,
  `get_recipe_bake`, `add_recipe_bake`, `list_library_recipes`, `get_library_recipe`, `use_recipe`,
  `propose_recipe_save`, `import_recipe`, `export_recipe`, `set_recipe_keys` and `get_recipe_pose`,
  all in the animation group.
- **Grips (4):** `list_grips`, `get_grip`, `apply_grip` and `propose_grip_save`. The animation group
  now holds 24 tools.
- **Prepare (2):** `render_views` and `get_model_facts`.
- **Built (1):** `replace_with_built_asset`.

- **People decide.** `add_recipe_bake` waits for your approval and the card opens the review.
  `propose_recipe_save` and `propose_grip_save` raise a card whose Review opens the save sheet, and
  only your Save writes. No tool removes from the recipe or grip library.
- **Versions.** Recipe reads answer `version`, a hash of the file. Changing lists needs `expected`
  (`needs-version` without it, `moved` when the file changed), so an agent never writes over an edit
  it did not read.
- **Refusals with a fix:** `open-blanks`, `staged-bake`, `stale-bake`, `bake-changed`,
  `library-import`, `clip-in-use`, `recipe-too-big` and `job-in-several-projects`.
- `run_rig_doctor` gains the step `rigid` (`parts`, `bone`), `list_built_assets` adds `replaced`,
  `get_ship_plan` adds `swaps`, and `send_to_3d` by hand answers `exportName`.
- **Skills.** `maquette-animation-recipe` covers the recipe flow, its error codes and the steps only
  a person takes. `maquette-built-rebuild` carries the recipe for rebuilding a generated model as a
  built asset: facts first, at least three render rounds with a fault list each, a dry run, the swap,
  then a stop before Ship. The plugin is now 0.6.0, and the server instructions name both skills.

## Fixes

Found by trying the recipes in the real app:

- A fresh bake no longer reads as out of date after Save to library.
- The hand gap of a bake (58.6 cm against the preview's 6 cm on one character) came from Blender's
  bone shape mesh being measured as part of the model. The bake now leaves bone shapes out, and the
  preview moves targets with the model, so the two agree (2.4 cm against 6 cm on the same job).
- Denying an agent's recipe save toasted "Run null stopped". Every approval kind now has its own
  toast, and a new kind fails the typecheck instead of falling into Ship.
- The prop picker no longer offers the model being animated, and the core refuses a bake whose blank
  holds it.
- A bake reports its frames the way the clip library counts them, and a 60 frame rest pose plays the
  full 2 seconds.
- The Wave hello starter runs 60 frames, like a new rest pose recipe.
- Importing or copying a recipe whose name is taken gives `Name (2)`.
- The Save to library footer wraps, the recipes list scrolls clear of an approval card, a disabled
  Save no longer looks primary, the change kind picker is no longer cut off, the "merged with yours"
  note clears after a save, and a recipe edited by hand is read again when the window regains focus.
- A bake finishing during a status read no longer reads as "The app closed during this bake".

Older features:

- A model left in the Inbox by a removed project could link, after a restart, to another project's
  send of the same id, so its accept and redo went to that project's asset. A bare id now never links
  an inbox file to a send that is over or made after the file was written.
- Use in the New models in Downloads dialog is disabled while its send imports again. A double click
  used to copy a large GLB twice.
- The Ship approval card's Approve tooltip on a website named the game repo.
- `run_pipeline`'s text said Ship always waits for approval, which was not true for a website with
  Ask before shipping off. It now states the real rule.
- A built asset build that fails because the script imports `maquette_helpers` without listing it
  says what to list.

## Known limits

What backs this release is automated tests, real headless Blender runs in the test suite, a real MCP
client in the tests, mock mode and a visual check per change. The first recipe slices (#142 to #147)
were tried by hand in the real app, and the two fix rounds above came out of that.

**Not run by hand:**

- The recipe fixes themselves, after those hand tests, and everything from round 2: joined clips,
  pins, pose keys, grips, seam checks, fixes, agent drafts and the combat starters. They were seen in
  mock mode and baked in headless Blender tests.
- Recipe export and import through the native save and open dialogs, the recipe library under
  Syncthing, and an agent over a live MCP session raising a recipe or grip save card.
- The combat starters on real sword and scythe clips: their clip names are guesses at common names.
- The stricter ship gate, a built asset replace and its undo, render views, rigid parts and the walk
  row in the real desktop app, and a real Ship of a swapped model into a site repo.
- The rig doctor changes on the real winged character and the real +X character that prompted them.
  Fixtures stand in for them.
- A real workspace with sends from both numberings. An older version reading a workspace this version
  wrote was tried once by hand.
- Windows at all. CI runs the Rust tests on Windows, and that is the only Windows run.

Known gaps:

- **Your own runs** from the app into a repo or folders an agent set still ship with no card, and an
  agent can still write `maquette.site.json` into your repo without one. Nothing an agent runs ships
  into it without a card.
- **A swap shipped from another computer** is still named here, since swaps read this computer's run
  history.
- **The page light** matches the starter pipeline's baked light, not a page with lights of its own.
- **Unsigned builds.** A first install shows Gatekeeper's Open Anyway or SmartScreen's Run anyway.
- **macOS Keychain prompts** for each stored key after each update. Choose Always Allow.
- Avatar is still in early stages.

## Upgrading

- **Per computer state.** `state.json` (the app state on each computer, not in the workspace) gains
  `agentSetFolders`, the site repos whose folders an agent set. An older file loads with none, so
  folders an agent wrote before this version count as yours.
- **Sends.** `providers.json` stays version 1. Each record a new send writes carries
  `"scope": "project"`, and older records keep their ids, handoff folders and export names. An older
  Maquette that opens the workspace gives jobs that share an id across projects a fresh id, and its
  Downloads watcher does not read the new export names, so it asks about those files. If you share a
  workspace between computers, update them together.
- **New files in a project:** `recipes/` with recipe files and their draft marks, and
  `recipe-bakes.json` for models that came from a bake. A built asset that replaced a model keeps the
  record in its `built.json`; an older build of the app that rewrites that file drops the record, and
  the undo with it.
- **New folders in the library:** `library/recipes/` and `library/grips/`.
- **Starters.** A project made before this version shows `built/maquette_helpers.py` and
  `built/maquette_example.py` as new on the Pipeline view's starter banner. Update adds them and
  touches nothing you edited.
- **Agent skills.** The plugin is now 0.6.0 with two new skills, `maquette-animation-recipe` and
  `maquette-built-rebuild`. In Claude Code run `/plugin marketplace update maquette`, then update the
  plugin from the `/plugin` menu. With Codex, `git pull` the clone and run
  `node plugins/maquette/install-codex.mjs` again: it links each skill folder, so new skills need a
  new link.

## Install

Download the `.dmg` (macOS, Apple silicon) or the `-setup.exe` (Windows x64) below, or update from
the app. The builds are not signed by Apple or Microsoft yet, so a first install shows Gatekeeper's
"Open Anyway" or SmartScreen's "Run anyway" once. Install guide:
https://shironex.github.io/maquette/docs/start/install/
