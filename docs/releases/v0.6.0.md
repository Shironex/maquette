# v0.6.0: First run, agent start and a faster gate

The fifth update after the public release. v0.5.0 added a lot, and this one is mostly cleanup and
quality of life: a Board header with one main button, a first run that tells you the next step, an
agent that can start from nothing, one look for waiting, a record of who answered each paid send,
and a gate that runs in parallel lanes. Most of it has only been tried with automated tests and
mock mode, plus one real app pass on 2026-11-02. The Known limits section says exactly what I ran by
hand and what I did not. It is still early: back up your workspace before you update.

## Highlights

- **A Board header with one main button,** grouped menus with a reason under every disabled item,
  and approval cards that fold.
- **First run:** a next step strip on the Board, a Blender trouble screen, concept images imported
  from disk and refs added from disk.
- **Agent start:** `get_started` and `create_project` let an agent begin with only the MCP
  connection.
- **Waiting looks the same everywhere:** a verb, a count when the work reports one, and how long the
  same wait took last time.
- **Approval log:** every answer to a paid send is kept in `approvals.jsonl` and shown on the send.
- **Shorter avatar answers** from `set_avatar` and `get_avatar`.
- **Highlight softening is refused above 5 percent,** so it stops painting blotches on skin and hair.
- **A provider jobs race fixed:** closing a workspace during a save could empty `providers.json`.
- **A parallel gate** (`pnpm gate`) and a `pnpm gate:fast` that checks only what changed.
- **MCP tools from 118 to 120.**
- **Node 22.23.4 is now the floor.**

## What's new

### Board header and menus

The header picks one main button from the project's state: Run pipeline is bright once a model
exists, Add before that, and nothing while a run is going or while the first run tips lead. Every
menu has sections, count badges and a second line that says why an item is disabled. The card menu
is grouped Make, Asset and Move with Remove last, a waiting card leads with By hand, and the rig
doctor item is hidden only when a model is known to have no joints. The card's dots target is 40 px
and "Update to v3" now reads "Library has v3". Export pack opens over the Board, loads on demand and
closes when you change project.

Approval cards fold: the details and the answers render only when a card is open. Approve holds for
500 ms after a card opens, folds, arrives, leaves or moves, and when the window returns, so a click
meant for something else cannot approve. A menu ignores the second click of a double click for 600
ms after it opens. "3D queue" is called Sends in the MCP text, the mock and the README.

### First run

- **Next step strip.** One sentence and one button for the most blocking step: Blender trouble,
  models waiting in the Inbox, refs to send, a failed or cancelled run, or no repo. You can dismiss
  it, and the dismissal belongs to that project and that step.
- **First run card** on an empty project, and a Blender missing screen in onboarding and in
  Settings that checks again when the window gets focus.
- **Setup copy and defaults:** recommended defaults in onboarding, plain project names, a line on
  what each template creates, and Run pipeline held (with the reason shown) while a project has no
  models.
- **Concept image import.** Drop or choose PNG, JPEG or WebP files on the Concept column and they
  become a Lab direction and a Concept card. The type is read from the file header. The limits are
  50 MB per file, 50 images and 512 MB per drop, and one bad file stops the whole import with its
  name.
- **Add refs from disk** in the refs sheet. It runs the same checks and never replaces a file: the
  same bytes reuse the file and different bytes get a free name such as `front-2.png`.
- New folder ids avoid names Windows reserves (`con` becomes `con-1`). Old ids stay valid.

### Agent start

An agent with only the MCP connection and the skills can now start from nothing.

- `get_started` (read only) reports the workspace, each tool of the toolchain, whether each key is
  saved (never the value), the image backend, Ask before shipping, the projects with target and
  stage, the gates only a person can pass, and a `next` list. It works with no workspace open.
- `create_project` takes a name, a kind, and optionally a template and a site repo, on the same path
  as New project. It refuses a taken name, spends nothing and there is no delete tool.
- Empty or dead end answers carry `next` hints, waiting answers carry `pollEverySeconds` and
  `whereToApprove`, and errors are JSON with the real `code` and a `fix` where one helps.
- The MCP instructions went from about 15 KB to under 4 KB, and the longest tool descriptions were
  trimmed. Tools carry a `[group]` tag, and the seven avatar and rig tools can be switched off in
  Settings > Agents.
- `set_ship_settings` takes `siteRepo` for website projects.
- The first start of a dev server in a repo an agent set waits for a person on one approval card,
  and asks again when the folder, command, `package.json` or a package manager config changed.

### Waiting states

Waiting is one recipe now: a verb label, a count when the work reports one, and how long the same
wait took last time (`last 12s`). A past time is only kept for a wait of 2 s or more, never for a
failed or abandoned one, and nothing guesses a time. The recipe is applied to the Inspector tabs,
Models, Motion, Inbox, Lab, rig doctor, render and parts. The rig doctor opens at once with
"Reading the rig of X...", an untested case says "Not tested yet", and its actions say why they are
disabled. Open in Blender shows a toast straight away. Board cards show "Rendering a preview" until
the picture lands, and Move to is optimistic with a rollback and a toast if it fails. First view,
Scene budget and the Motion meter say "Reading..." instead of a fake zero.

### Shorter avatar answers

`set_avatar` answers with what changed, the spec and any problems, and `get_avatar` answers with a
summary; `include: ["bones"]` or `["joints"]` adds the full lists. On the default humanoid test
fixture (55 bones, 65 joints, so not a real character) the two answers together went from 9,125
bytes to 2,333 for `get_avatar` and 601 for `set_avatar`. A spring is now confirmed by candidate id
and the server fills in `line` and `drop`.

### Approval log

Every answer to an approval (approved, denied, expired or cancelled) goes to `approvals.jsonl` next
to `credits.jsonl`: the time, the request, project, jobs, provider, estimate, and who answered, with
the source (floating card, Settings > Agents, Ship view, Avatar, rig doctor, cancel, quit or
workspace change), the input (pointer or keyboard), what the page reported and the window state read
from the system. The record is written before an approval is released, so an approve that cannot be
written is refused and the reason is shown. Opening or creating a workspace expires every waiting
approval and releases nothing. The Credits sheet shows "approved 07:39 in the floating card" under
an agent's send, and `get_provider_job` and `get_credits` return the decision. Only the approval
cards can approve: `mcp_decide` refuses any other source and a test scans the MCP module for any
other way to answer. A record shows what the app saw, not proof that a person pressed.

### Ship with no repo

A Ship step that needs a site repo is now left out of the run when the project has none, and the run
says so (`shipped` and `shipReason` in `get_run` and `run_pipeline`) instead of looking shipped. The
Pipeline shows a "Not shipped" node, the Board header a chip and the status bar "Run N done, nothing
shipped". Run pipeline asks first in a new dialog.

### Game templates

Seven more game templates (Web game, Godot, Unity, Unreal, Mobile, VR standalone and Game jam) can
set the texture format, the texture size cap and whether normal and metal-roughness maps are
dropped. All of them write `.glb`. Their per model numbers are my judgment, not published limits,
and the text says so; the only published figure is Meta's whole view limit for Quest 2 and Quest 3.
The picker groups the templates and shows format, textures and budgets on each card. `get_game`
lists every template and `previews` adds what each would change.

### Smaller changes

- The Sends button stays on show after a failed send and its tooltip lists the failed ones.
- Parts says "Reading the parts" while it only reads, and the Export pack sheet shows a loader or the
  error instead of a blank body.
- "Accept to Blender" is "Accept into project", "Zip 7 of 8" when not every model is in, and Lab
  Generate stays on screen while the panel scrolls.
- Rig doctor keeps the earlier draft: a fix writes `attempt.glb` and replaces `draft.glb` only when
  the round is done, so a round that moves nothing says "Round 2 changed nothing".
- `PackRecord.leftOut` replaces reading the count from a message, and `layout::update` is now the only writer of `layout.json`.

## Bug fixes

- **Provider jobs race.** Closing the jobs (a workspace switch, quitting, the updater) could
  overwrite a project's `providers.json` with an empty or cut down list and lose send records and the
  saved chain a running paid Tripo or Meshy job resumes from. Saves now hold a lock that `close()`
  waits for, nothing writes once closed, and each workspace open has a generation so a stopped
  worker cannot land on a same-id job in the next workspace.
- **Highlight softening** leaves an image alone when more than 5 percent of it reads as baked
  highlights, and says why in the note. On an atlas with pale and dark parts, islands that touch were
  taken for shine, which put brown and grey blotches on skin and hair. This is a limit, not better
  detection: a real shiny texture above 5 percent is kept as well.
- **Every rail view fits the minimum window** (1120 by 720): the Board list, Inbox, Motion, Lab,
  Settings, Page, Pipeline and Animations headers wrap or narrow instead of clipping.
- Export pack no longer stays open over another project, and a failed load leaves the shell up.
- A Move to that fails returns each card to the last stage the core confirmed.

## Performance

- **The full gate did not get measurably faster.** It is about 6m02 before and after on a machine
  that was never quiet. The lanes run side by side but Vitest, Clippy and nextest each take every
  core. `pnpm gate:fast` took 2.2 s for a docs line and 2m00 for one web file at load 21 to 42.
- A clean Rust target went from 7.0 GB to 5.6 GB, because the dev profile keeps line tables only
  (debugger locals are lost) and the desktop binary no longer links an empty test binary.

## Accessibility

- `pnpm a11y` runs 38 cases with 0 critical or serious findings. Four older moderate or minor
  findings remain.

## Under the hood

- **The gate.** `pnpm gate` is `scripts/gate.mjs`: a Node lane and a Rust lane side by side, the heavy
  steps taking turns, with a summary and logs per step. Rust tests run under cargo-nextest when it is
  installed, plus `cargo test --doc`, and fall back to `cargo test`. The gate now fails if the Rust
  tests rewrite a generated file. Stopping it stops the whole process tree and a stopped gate never
  reports success. `pnpm gate:fast` checks only what changed since main and runs the whole gate for
  files read across parts of the repo.
- **MCP tools** went from 118 to 120: `get_started` and `create_project`.
- **Skills** share a "before you start" block, checked word for word by `scripts/check-skills.mjs`.
- Provider jobs take the sending lock, then the save lock, then the jobs list, always in that order.

- zustand 5.0.16 and @tanstack/react-virtual 3.14.22.

## Known limits

I want this to be clear about what has and has not been run for real.

**Run by hand in the desktop app on 2026-11-02, against main `d5ef340e`:**

- The short `set_avatar` answer.
- The `get_credits` decisions.
- A fresh agent running `get_started` and `create_project` with no Keychain prompt.
- Picking a concept image, and a bad file refused by name.
- Refs Choose from disk, which did not overwrite a file.
- The Run pipeline disabled reason.
- The next step strip, dismissed per project.
- The card menu double click.
- An agent's denied paid send recorded in `approvals.jsonl`.
- Send records still intact after switching projects.

**Not run by hand:**

- A workspace switch while an approval is waiting.
- The Approve hold.
- The Blender missing screen.
- The soften refusal on a real avatar.
- Windows at all. The parallel gate, the first run flows and the provider jobs race only ran in CI
  there.

Everything else was checked by automated tests, real headless Blender runs where Blender is involved,
and mock mode.

Known gaps:

- **Windows needs Node 22.23.4** or the gate fails, because `astro check` refuses to start on older
  Node.
- **The full gate is not faster,** only `pnpm gate:fast` is, on a change that touches little.
- **Unsigned builds.** A first install shows Gatekeeper's Open Anyway or SmartScreen's Run anyway.
- **macOS Keychain prompts** for each stored key after each update. Choose Always Allow; macOS may
  ask for your password.
- **Highlight softening is refused above 5 percent,** so a texture that really is shiny is also
  left as it is.
- **A damaged or truncated image imports** and shows as a broken tile, because only the header is
  checked.
- **The approval log shows what the app saw.** Expiry is recorded only on a clean quit or a workspace
  switch, not on a crash, and the file only grows.
- **A refused By hand send** leaves its already written handoff folder behind.
- Game template numbers are my judgment and the Meta figure was not re-checked against Meta's page.
- Avatar is still in early stages.

## Install

Download the `.dmg` (macOS, Apple silicon) or the `-setup.exe` (Windows x64) below, or update from
the app. The builds are not signed by Apple or Microsoft yet, so a first install shows Gatekeeper's
"Open Anyway" or SmartScreen's "Run anyway" once. Install guide:
https://shironex.github.io/maquette/docs/start/install/
