# v0.7.0: Planning canvas, MCP tool groups and removing a project

The sixth update after the public release. The big addition is the planning canvas: node canvases
inside a project where you and your agents can plan with notes, pictures, links, live assets and Lab
directions, and a website's camera plan. Around it, Settings > Agents can now switch whole groups of
MCP tools off, a whole project can be removed to the workspace trash and restored, and the v0.6
polish list is done. Most of it has been tried with automated tests, mock mode and visual checks per
change. The Known limits section says what I did not run by hand. It is still early: back up your
workspace before you update.

## Highlights

- **Planning canvas:** a Plan view under Board with canvases per project, made of notes, pictures,
  links and edges, with undo and redo, autosave and a minimap.
- **Live nodes:** asset nodes and Lab direction nodes read their name, thumbnail, stage and state
  from the project each time, so nothing goes stale.
- **Agents on the canvas:** 14 new MCP tools, a per canvas change log, Undo per change or per agent
  run, and a rule that agents never remove your nodes. They ask with `propose_removal`.
- **Website camera plan:** a built in canvas of camera stops that only reaches `layout.json` after
  you review the exact diff and press Apply.
- **Presets:** Brainstorm, Story and Game mechanics, plus empty states and recent canvases on the
  rail.
- **Mechanics overlap check:** two Game mechanics cards that share a verb, look or input are flagged,
  and you can Mark as fine.
- **MCP tool groups:** Settings > Agents lists the groups with a switch each, so a session pays
  context only for the tools you use.
- **Remove a project** to the workspace trash and **Restore** it from Removed projects.
- **MCP tools from 120 to 134.**

## What's new

### Planning canvas

Each canvas is one plain JSON file at `<project>/plans/<id>.plan.json`. The id is made from the name
once and kept on rename.

- **Plan view.** A Plan item under Board lists recent canvases as cards and all of them in a table
  with search, New canvas, inline Rename and Remove (the file moves to the workspace trash).
- **Notes, pictures and links.** Draw edges from any side, pan, zoom, select, move and delete. The
  floating bar adds a Note, Image or Link (N, I, L), and a double click on empty canvas writes a note
  there. Pictures come from the project (linked by relative path) or from disk (copied once into
  `plans/images/`). Links open in the browser (https only) or copy their address.
- **Saving.** Every change saves a moment later and the top bar shows `saved`, `saving` or a failure.
  Leaving a canvas saves the latest edits first, and if that save fails you can Try again, Stay or
  Leave without saving. Quitting with unsaved canvas edits goes through the existing quit question.
- **Undo and redo** of your own edits: buttons in the top bar and Mod+Z, Shift+Mod+Z and Mod+Y, a drag
  is one step, 100 steps. An undo never takes back an agent write that landed in between.
- **Outside edits.** The open canvas follows changes made outside the app (an agent, a sync) without
  losing your unsaved edits.
- **Minimum window.** Below 960 pixels of canvas width the minimap folds into a Map button, and the
  first fit and Fit leave room for the add bar, the zoom and the map.

### Live asset and direction nodes

An Asset tool (key A) opens a picker of the Board's assets and the Lab's directions. A linked node
stores only the id, and the name, thumbnail, kind, stage, newest version, model numbers and state are
read from the project each time, so a rename on the Board shows on the next read.

- **Asset states:** Model ready, Model to check, No model yet, File missing, and not found for an
  asset removed from the Board (dashed, muted, shows the id). A missing asset is a state, not an
  error, and the file opens and saves as before. Each state has a next step button (Open in
  Inspector, Open Inbox, Open Lab, Open Board).
- **Direction states:** Lab round running, Picked, Pick images, No images yet, Not in the Lab. Its
  next step opens the Lab on that direction. A direction counts as running only while one of its
  images is being made, so a round the Codex usage limit holds is not polled for hours.
- Empty cases say what to do: restore a removed asset from Removed on the Board or delete the node,
  and an empty picker says where assets and directions come from.

### Agents on the canvas

Agents read and write canvases over MCP and every write is logged.

- **Tools:** `list_canvases`, `get_canvas`, `get_changes`, `create_canvas`, `add_nodes`,
  `update_nodes`, `remove_nodes`, `layout_canvas` and `undo_run`, then `get_camera_plan`,
  `propose_camera_plan` and `get_apply_preview` for the camera plan, then `propose_removal` and
  `start_from_node`. That is 14 tools.
- **Change log.** One line per write in `plans/<id>.log.jsonl`, shown in a Changes panel beside the
  canvas with runs, All / Agents / Mine filters, Undo per change and Undo run. A toast appears when
  an agent writes, the top bar shows an agent chip, and agent nodes carry an "added" or "edited"
  badge and a blue ring.
- **Agents never remove a person's nodes or links.** The call is refused with a reason. A node under
  another agent's name is refused too, as a courtesy: agent names are labels, not accounts, so the
  real protection is between you and agents.
- **`propose_removal`.** An agent asks to remove nodes with a reason. The ask shows at the top of
  Changes and as an "asked to remove" badge on the node, and only you answer: Keep it, or Remove
  (your own undoable change, which also takes the node's links). No tool accepts or dismisses a
  proposal, and `undo_run` refuses the ask. A proposal goes stale when the node's content changes.
- **`start_from_node`.** Makes a new canvas from a node and the nodes linked to it by one link, as
  one undoable first line. In the app it is "Start a canvas from this" over a selected node.
- **Auto layout after agents** (a switch in the canvas header, on by default, each change logged and
  undoable). When on, `update_nodes` moves the agent's own edited nodes that now overlap another,
  inside the same change. A node you moved, or an agent node you wrote into, is never moved. When off,
  `layout_canvas` is refused and the agent places nodes with x and y.

### Website camera plan

A website project gets a built in Camera plan canvas, made from `layout.json` the first time it
opens: one stop node per camera stop, with its poster render where Capture posters made one, joined
in tour order.

- Reorder, add, remove and edit stops (name, position, target, fov) on the canvas or in the side
  panel. Edits save only to `plans/camera-plan.plan.json`.
- **Apply** opens a review of the exact diff against `layout.json` as it is now, including stops that
  moved and the triggers and timeline keys that go with a removed stop. It writes atomically and logs
  the Apply as your change. It refuses and writes nothing when either file changed since the review
  was shown.
- **Undo of an Apply** puts the kept `layout.json` back, only while `layout.json` is still what that
  Apply wrote.
- When `layout.json` changes underneath, the panel offers Compare, Rebase and Start over. Neither
  side is overwritten silently.
- Agents read the plan, propose a tour as their own line and edit single stops. No MCP route applies a
  plan or undoes an Apply. Game projects are refused.

### Presets, empty states and recent canvases

- **Presets** set only what a canvas starts with, as plain notes you replace. Brainstorm is blank.
  Story has 8 notes and 7 links (four beats, two characters, two places) worded for a game or a
  website. Game mechanics has 4 notes: Core action, Movement and Defence system cards with `Verb:`,
  `Look:` and `Input:` lines, and a "Keep them apart" note. A seed is the canvas's first log line, so
  one undo takes it back.
- A **preset picker** in the New canvas dialog and in the empty Plan list. `create_canvas` takes a
  preset and refuses an unknown one with the list.
- **Empty states:** no canvases (with a prompt to copy for an agent), an empty canvas, a camera plan
  with no stops or no posters yet.
- **Recent canvases on the rail:** Plan lists the three canvases opened or edited last, with a dot on
  one edited since you last opened it.

### Mechanics overlap check

On a Game mechanics canvas, two system cards overlap when a `Verb:`, `Look:` or `Input:` line comes
down to the same main word. An Overlaps button with a count opens a panel (Show, Mark as fine, a
Marked as fine section) and each card shows a flag such as "Same key as System: Dash (shift)". Mark
as fine is per pair and lapses when either card changes. Agents read overlaps in `get_canvas` but
cannot mark a pair as fine.

### MCP tool groups

Every agent session used to pay context for all the tools. Settings > Agents now lists the tool
groups with a title, a tool count and a switch, and shows "N of 134 tools offered". The start and
project groups are always on.

- A tool of an off group is left out of `tools/list`, and a call to one runs nothing and answers
  `group-off` with a fix naming Settings > Agents. `get_started` names the groups that are off.
- The server tells connected agents when the groups change (`notifications/tools/list_changed`). A
  client that ignores it keeps its list until it reconnects, and its calls to an off group are still
  refused.
- The server instructions and the skills tell an agent to ask you to turn a group on instead of
  working around it.
- **Settings file.** `agents.rules.toolGroupsOff` replaces `avatarRigTools`. A workspace with only
  `avatarRigTools: false` opens with the avatar-rig group off. For one release a save still writes
  `avatarRigTools` beside the list, so a computer on v0.6 that shares the workspace over Syncthing
  keeps the setting. When both are present the list wins.

### Remove a project

Remove in the project switcher and Remove project in Settings > Project ask first, naming the
project. The folder moves to `trash/_projects/` with its own asset and canvas trash, and the site or
game repo on disk is never touched. Removed projects in the switcher lists them, and Restore puts
one back and opens it.

- Restore never writes over a project that took the id, and a repo path that comes back is marked as
  set by an agent, so its dev command waits for a person again.
- Removing is refused, with the reason, while work runs in the project: a pipeline run, a built asset
  building, concept images in progress or any send that is not over. The Remove button greys out with
  the reason. Paid sends are never cancelled and `providers.json` is never touched.
- Removing the open project opens the next one, and the notice offers Undo.
- No MCP tool removes or restores a project. A removed project leaves `list_projects`, and a tool
  given its id says it was removed and only a person can restore it.
- A folder move never loses data: it renames (retried on Windows while a file is held open) and
  copies only across volumes. If removing the source stops partway, both folders are kept and the
  error names both.

## Bug fixes

These are the v0.6 polish items, fixed in the project removal change.

- The Next step strip counts only the open project's Inbox models, so an empty project never shows
  another project's.
- A denied paid send shows Denied on its job, the card says "Denied, not sent to <provider>" and goes
  back from the 3D model column to Refs while it has no model and no other send on its way.
- `create_project` takes `target`, the word `list_projects` returns, and `kind` still works.
- `get_started` is short by default and `detail: true` gives everything.
- Plurals: "1 image", "1 model", "1 send" across the app and a few core strings.
- Dollar sums never show `-0.0`.
- Clicking a switch in a scrolled Settings column no longer scrolls the whole document and blanks
  Settings: the hidden input now stays inside its label.
- Canvas fixes found along the way: edge labels draw on the panel colour instead of black boxes, a
  node a person moved stays put when agents tidy, a removal proposal reads its links again and
  refuses when they changed, and the camera plan's Rebase refuses when `layout.json` changed.

## Performance

- Overlap checks are cached (16 canvases) by what the check reads, so moving cards and drawing links
  never re check. The search is bounded at 32 main words per card and 500 pairs.
- A direction counts as running only while an image is being made, so the canvas does not poll for a
  round that is held.

## Accessibility

- New views were checked with axe in the a11y run (Settings > Agents tool groups, removing a project
  and the canvas extras), with no violations reported in those PRs. I did not re-run the whole
  `pnpm a11y` suite for this release note.
- The recent canvas dot is announced as "changed since you last opened it".

## Under the hood

- **Plan files** have a versioned schema with a migration chain. Plain canvases stay version 2. A
  file is written as version 3 only when it has camera stops, and as version 4 only when a setting
  such as auto layout off is used, so an older app keeps opening plain canvases. Opening a file
  never writes, and a file from a newer version is never saved over.
- All writes (yours, an agent's and an undo) go through one core path that takes the lock, lays
  operations by node and edge id over the file as it is now, checks, caps at 8 MB and writes.
- **MCP tools** went from 120 to 134: nine canvas tools, three camera plan tools, `propose_removal`
  and `start_from_node`.
- The docs site, README, architecture notes, server instructions and skills describe the canvas, the
  tool groups and project removal.

## Known limits

I did not run a full hand test of this release in the real desktop app the way I did for v0.6. What
backs it is automated tests, real MCP client tests, mock mode and a visual check per change. The
planning canvas was used in the real app with an agent before the last two changes landed: canvases
from each preset, notes, pictures, live asset and direction nodes, a link node, labelled links,
`start_from_node`, an overlap, a removal proposal and a camera plan proposal on a website project.

**Not run by hand:**

- Apply and Undo of a camera plan, answering a removal proposal and Mark as fine in the real app.
- Removing and restoring a project, and the tool group switches, in the real app.

- Windows at all. The retry of a held folder move and the canvas file watcher only ran in CI there.
- A second computer on v0.6 reading the `avatarRigTools` setting over Syncthing.
- An agent client that honours `list_changed`, beyond the tests that connect a real MCP client.

Known gaps:

- **Agent names are labels, not accounts.** The only protection is between you and agents.
- **A client that ignores the tool list change** keeps its list until it reconnects.
- **Running work blocks removing a project.** Rig doctor, renders and export packs are not checked,
  and a small race between the check and the move is accepted.
- **Removed projects have no permanent delete,** the same as the asset trash.
- **Unsigned builds.** A first install shows Gatekeeper's Open Anyway or SmartScreen's Run anyway.
- **macOS Keychain prompts** for each stored key after each update. Choose Always Allow; macOS may
  ask for your password.
- Avatar is still in early stages.
