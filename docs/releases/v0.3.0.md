# v0.3.0: Codex usage, OpenAI images in the Lab and downloads matched by picture

The second update after the public release. The Lab now shows how much Codex usage is left and can
make its images with OpenAI's Image API within a monthly cap. Downloads from the 3D sites are
matched to their sends by how they look, a model file you fixed by hand can become an asset's next
version, and a round of fixes from using Maquette on real projects covers game export, retargeted
clips and fix-ups. It is still early: back up your workspace before you update.

## Highlights

- **Codex usage in the status bar**, with the Lab timing and lifting its usage limit from it.
- **OpenAI's Image API as a second Lab backend**, chosen per kind of job, with a monthly cap in
  dollars, a spend ledger, and an approval before an agent's paid round runs.
- **Lab job control:** cancel, Run next and retry for held jobs, and jobs that survive a restart.
- **Downloads matched by picture:** a download no name matches is ranked against the waiting sends
  by how it looks, and late downloads are suggested instead of refused.
- **Add a model file** you fixed by hand as an asset's next version.
- **Retargeted clips keep their frame rate:** 30 fps clips no longer play 25% slow.
- **Game export:** a folder per asset, a game repo override, each rig's own clips and a switch to
  drop normal and metal-roughness maps.
- **MCP tools from 85 to 92.**

## What's new

### Codex usage

The status bar shows "Codex 16% (5h) · 3% (week)" while you are in the Lab or jobs are running:
amber from 80%, red at 100%, with each window's reset time in the tooltip. Maquette reads it
through `codex app-server` every 60 seconds while the Lab is open, and again right after a job
finishes or meets the limit. When the usage limit holds the queue, the waiting banner counts down to
the real reset, and "Limit lifted, retry now" checks again before it runs the held jobs. A round of
four or more images warns first when a window is at 80% or more. A Codex that is missing or older
than 0.130 reads as unknown, with the reason.

### OpenAI Image API in the Lab

Lab jobs can run on OpenAI's Image API as well as on Codex. Settings > Image generation picks the
backend for each kind of job (concepts, object refs, other views, clean background); Codex stays
the default. The API key lives in the keychain and is never written to a file, and "Test key" only
lists models, which costs nothing. You also choose a quality (low, medium or high, each with an
estimate per image) and a monthly cap in dollars, and Settings shows what was spent this month. Every
image is written to the credits ledger in dollars, and the cap uses the average of the last measured
images once there are enough. A refusal by OpenAI's safety system fails the job with the reason,
says nothing was charged and leaves no ledger line.

### Approval for agents' paid rounds

When an agent starts an image round on the OpenAI backend (`start_concepts`, `make_object_refs`,
`make_other_views`, `clean_ref_background` or `retry_concept_jobs`), its jobs wait in the app with
the estimate and the month so far. Approve releases them; Deny cancels them and nothing is sent.
Rounds you start in the Lab and Codex rounds never ask. Over MCP an agent can change the backend and
the quality, but never the monthly cap: only a person sets it, in Settings.

### Lab job control

Waiting, running and held jobs can be cancelled, and **Run next** moves a project's queued jobs to
the front of the line, in the queue and from MCP. Retry takes failed, held or all jobs. Unfinished
and failed jobs are kept in `lab-jobs.json`: after a restart, jobs whose image landed come back
done and the rest come back failed with "Interrupted by a restart", ready to retry. Nothing is sent
again on its own.

### Views

Make the other views takes notes (up to 400 characters) for every view's prompt. Using a drawn view
now replaces the ref in its slot and moves the old one to `refs/originals`, unless another asset or
a send still uses it. The UI has a "Replace Left" action.

### Downloads matched by picture

A download that no send's name matches is rendered from the front with headless Blender and ranked
against every waiting By hand send by outline, colour and shape. A clear best is suggested on the
look card next to the send's front ref ("N% alike"), with the other sends one click away. Nothing
attaches on its own. Late downloads are no longer refused for coming long after the sends, and
`list_handoffs` returns the ranked suggestions. FBX downloads are still matched by name only.

### Add a model file as the next version

A card menu item and the `add_model_file` tool (with an optional `accept`) take a model file someone
fixed by hand in Blender or another tool as an asset's next version. glTF, FBX and OBJ are
converted to GLB headless. The file is copied, never moved.

### By hand settings

The By hand settings card carries the mesh (HD Model or Smart Mesh P2.0) and the rig (biped,
quadruped, multi-legged or none), in the send and batch panels and as `mesh` and `rig` on
`send_to_3d`, `send_batch_to_3d` and the redo tools.

### Game export

- A game asset can ship to a folder of its own under the models folder (kit, enemies, characters),
  set in the Budget tab's Game folder column or with `set_game_settings`. The ship plan lists the
  old file under Removed, and Ship deletes it only if Maquette wrote it.
- `run_pipeline` and `get_ship_plan` take a one-off `repo`, checked to be a git checkout or
  worktree, so an agent can ship into a worktree. Ship still waits for approval.
- Each rig's export carries only its own clips.
- A `dropMaps` setting (off by default) leaves out normal and metal-roughness maps for shaders that
  read neither.

### Rotate fix-up

A new fix-up turns a leaning model upright by X, Y and Z degrees, with no credits. It is in the
fix-ups list and in `add_fixups`.

### Agents

MCP tools from 85 to 92: Codex usage (`get_codex_usage`, `retry_usage_limited_jobs`), the image
backend (`get_image_backend`, `set_image_backend`), Lab job control (`cancel_concept_jobs`,
`prioritize_concept_jobs`) and `add_model_file`, plus new options on existing tools. Tool
descriptions no longer say "Codex" for every image backend, `list_library` is compact and paged by
default, and `get_concepts` can limit jobs to one direction. If your client does not list the new
tools, reconnect it.

## Bug fixes

- The compare menu shows asset names alike, and the terse reset, test, copy, download and dismiss
  buttons have tooltips.
- Retargeted clips are baked at their own frame rate, so 30 fps clips no longer play 25% slow, and
  the trim keeps the clip's last frame.
- A sync conflict copy of the workspace lock file is removed quietly instead of raising the
  conflict banner. Conflict copies of real data files are still reported, never merged.
- Sending an asset that already has a library model warns first.
- The first view's status dot no longer leaks into model names read by screen readers.

## Under the hood

- CI skips the typecheck, web tests, site build and Rust jobs when a change only touches docs.
- The README images are reshot and show the v0.2.0 features, and the landing page offers the
  download for the visitor's platform.

## Install

Download the `.dmg` (macOS, Apple silicon) or the `-setup.exe` (Windows x64) below, or update from
the app. The builds are not signed by Apple or Microsoft yet, so a first install shows Gatekeeper's
"Open Anyway" or SmartScreen's "Run anyway" once. Install guide:
https://shironex.github.io/maquette/docs/start/install/
