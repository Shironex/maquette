# v0.5.0: Export packs, rig doctor and a 3D quick view

The fourth update after the public release. It is mostly about working with more models at once and
fixing them in the app: a 3D quick view, a table for the inbox, a library that copes with a few
hundred models, export packs, a rig doctor, render styles and game templates, plus a round of small
gaps in the timeline, the page view, version compare and the retarget wizard. It is a big release
and most of it has only been tried with automated tests, real headless Blender runs and mock mode.
The Known limits section says exactly what I ran by hand and what I did not. It is still early:
back up your workspace before you update.

## Highlights

- **3D quick view:** open one model in a modal from the Board, the Library or the Inbox.
- **Inbox triage:** go through many models in a table, with bulk accept, discard and restore.
- **Library at scale:** search, collections, bulk tags, look-alikes and adding a whole project.
- **Export packs:** write a set of library models as one folder and zip for another engine, each
  model checked again in headless Blender.
- **Rig doctor:** fix the skin weights of a rigged model on a copy, with before and after sheets,
  and land it as the next version.
- **Render styles:** blueprint, toon, clay, shaded, turntable and contact sheet pictures.
- **Game templates** for the export settings of a game project.
- **A tidier Board header:** one Sends button, a More menu and an Add split button.
- **MCP tools from 97 to 118.**
- **Nothing runs on the app's main thread any more,** so a macOS Keychain or folder prompt or a slow
  read can no longer freeze the window.
- **Rig doctor checked on real models:** readings on a robed humanoid and a quadruped now match what
  the models show.

## What's new

### 3D quick view

A modal over the Board or the Library that shows one model on the same preview the Inbox uses, with
Shaded, Wireframe, UV and (for a rigged model) Bones, a turntable and orbit and zoom. Open it from
"Inspect 3D model" in a Board card's menu, from a Library card's picture or from the Inbox preview.
Open in Inspector jumps to that version in the Compare tab. A model the project has not added says
so instead of opening.

### Inbox triage

The Inbox has a Table layout next to One by one. Models are grouped by what they need (Checks pass,
To review, Replaced by a redo, Unreadable), filtered with chips, and the selection bar offers Accept,
Redo, Accept and add to library and Discard. The side column says what Accept will do before it
runs. A discarded model is kept in `inbox/.discarded` with a note of where it was going, can be
restored, and is pruned after 30 days with the days left shown. An empty inbox shows a round
summary and the models you discarded recently.

New downloads are held while Blender is missing and matched by picture when it is back. The MCP
server got `accept_inbox_models` and `restore_inbox_model`, and `list_inbox` now also gives the
version Accept would make, what replaced a model and the discarded ones.

### Library at scale

The Models page works with a few hundred models: one search field (`tag:`, `in:`, `by:tripo`,
`<5k`), collections, a summary line with sorting, multi-select with Shift ranges, and a bulk bar for
Tag, Add to collection, Use in project and Remove with Undo. Look-alikes finds models that look the
same under two names or share one name, and merges them as versions with Undo. Add a whole project
puts a project's models in the library from one sheet, with a project tag, a collection and tags by
kind. A Group
menu groups the grid by what made a model or its kind. Seven library tools were added for agents.

### Export packs

Export pack writes a Library selection, a collection or a project's accepted models as one pack:
OBJ with MTL and textures, GLB or both, in a folder with a zip next to it. Each model runs through
headless Blender with its real size, fix-ups, triangle budget, texture size and bottom centre pivot,
then the written file is opened again in an empty scene and checked (triangles, height, floor,
textures that did not load, clips left). The pack gets a README, a manifest and a contact sheet.
Settings can be saved as presets. Mixamo clips are always left out, and the card, README and
manifest say so. The sheet shows each model's check, a Needs you list (Raise, Keep, Export again),
the time left, Stop and Go on. A decision on a stopped pack leaves it stopped. `export_pack`,
`get_pack`, `list_packs` and `decide_pack` do the same for an agent.

### Rig doctor

Rig doctor opens from "Fix in rig doctor" on an Inbox rig check or from a Board card's menu. It
reads the rig, runs a pose test and fixes the skin weights in headless Blender on a copy, then shows
before and after sheets with one verdict per row. Nothing lands until you add it as the next
version, and an agent's finished fix raises an approval card. There is a humanoid route (Mixamo bone
names) and a creature route with an editable Chains table that you check by hand, a one island
reweight, a walk clip proof on a copy and a Redo that opens the existing redo sheet. An inbox
warning now also flags cloth or hair weighted to the arm bones.

After the first rounds on real models the readings were reworked (see Bug fixes). Past the body is
now the stretch that 0.5 percent of the surface reaches, so a few sliver edges read as "look here" in
amber and stop nothing. Bones with no weight stay in the file but make no chain, and a line under the
chain table names them. A quadruped reads its four legs and one tail, the head chain starts at the
last bone with a real share so the head bends as a whole, a fix that moves nothing ends in a new
no-change stop and leaves no draft, and a round counts only once it made a draft. `start_rig_doctor`,
`run_rig_doctor`, `get_rig_doctor` and `list_rig_doctors` read and start it; none of them approves
or lands anything.

### Render styles

Blueprint, toon, clay, shaded, turntable and contact sheet pictures of a model, made by headless
Blender with no credits. The Render tab of the Inspector has styles, camera (including a project
camera stop), settings per look and a turntable sheet (WebP by default, GIF and MP4 with ffmpeg). A
batch sheet renders a Board or Models selection. Failures say what to do: Blender or ffmpeg
missing, a GIF over its size target, a toon render with no texture, a line pass out of memory (with
its log). `render_styles`, `get_render`, `list_renders` and `decide_render` are the MCP tools.

### Timeline and page

The timeline got a render style track (Blueprint, Toon or Clay) and hero text tracks, with lanes, a
key editor and `set_layout` support; older layouts still load. The landing page template plays them
as a CSS filter and as opacity on copy marked `data-maquette-text`. The Page view has a Hotspots
chip for click and hover pins, and a check for a scroll range that runs past a stop whose model list
leaves the prop out.

### Draw on surfaces

In the Paths editor, press `D` and drag on a model to lay cable path points along its surface,
lifted by the tube radius.

### Version compare

Provider vs provider on the Compare tab compares any two versions of an asset by triangles, draw
calls, GPU memory, transfer, real size match, texture detail, Inbox checks and credits, with a dot
on the better side and Keep buttons. A side panel says what keeping does and which camera stops see
the asset.

### Choice after a Meshy split

After a Meshy split the sheet offers Bake the texture back (the default, as before), Re-texture with
Meshy, or Keep it grey for now. A grey split keeps offering both in the Parts tab. Re-texture goes
through Meshy's `/retexture` and lands in the Inbox as the next version, only after a confirm that
shows the price. No MCP tool reaches it. The Parts tab can also tweak only the selected parts'
materials, export a GLB and open Motion.

### Retarget helpers

The retarget wizard can filter to humanoid rigs, shows a rough live preview on the model, draws
rest poses over each other with a T pose or A pose readout, and lets you choose what a bone only on
the model follows. Trim handles replace the number fields and Review has play, a scrub strip and
Accept as is. Library clips sit in their own group in Motion with a source line, a Compare banner
and a switch that leaves a clip out of a game file. The Animations library has Try on and a count of
use.

### Game templates

Four built in templates (Prop set, Character, Level kit and Level kit as .obj) fill a game
project's model format and the budget row of each folder they lay out. They add no assets and no
game code and never move or delete a file. Pick one in New project or with Use a template in the
Game export panel, which shows what would change before Apply. `set_game_settings` takes a
`template` and `get_game` lists what each would change. A model already in the ship record keeps
its path and format.

### Board header

The Board header went from eight buttons to Board | List on the left and Sends, a ... menu and an
Add split button on the right. Sends opens one panel with the 3D queue and By hand lists as tabs and
shows only while a send is in flight. Export pack, Render previews, All sends and Removed are in the
... menu. The count in Sends no longer counts a By hand send twice. The top bar's budget meters and
stage stepper turn compact at a narrow width, and an agent's approval prompt docks in the bottom
right so it leaves the header controls free.

### Packs and templates, after real use

- **Earlier packs** now lead the pack settings as two rows with Show all, each with Open.
- **Raise all and Keep all** in Needs you answer every model with the same warning type in one go.
- A finished pack counts a model with a warning that shipped as in the pack ("10 of 10 models are in
  the pack, 5 lost thin parts at their budget, kept"), in the Models tile, the triangles, the
  manifest preview and the tree.
- **Template preview** is true to what Export does: a game model that no import or Ship recorded
  but that has a file on disk keeps its path, and the template sheet's buttons stay in place with
  one Apply label. While a preview waits the sheet says it is reading, and says so when the read
  failed.

### Smaller gaps

A camera stop in the render tab, a Kept and Removed list under Clean background, a Generated files
list in the pipeline view, empty Motion links to the clip import, and the re-import check per file
type in a finished pack.

## Bug fixes

- Export pack pictures no longer break on macOS and Linux: the asset scope now names the one
  `exports/.packs` dot folder.
- Pack time left averages only models that ran, a Waiting tab counts the queue, the stop message
  says which model is next ("Stopped with 7 of 431 done, model 8 is next"), a stop during the last
  model finishes the pack, and a model that stays over its budget waits in Needs you.
- The Inspector's tabs in a game project no longer fall through to Compare when you pick Render or
  Parts: the tab row and the page read one list.
- A mock project's hero model file is registered, so the Motion stage shows the model.
- A clip name wraps to two lines in the Motion clip list.
- The keyboard can reach the scrolling chosen clips column in the Use on model dialog.
- Two flaky Rust tests no longer depend on a clock or a free port.
- Quick view and every dialog now hold focus themselves, so Escape still closes them after a press
  on something that takes no focus, such as a mode button or the 3D canvas.
- The minimum window (898 by 577) fits the Models header, the budget table, the status bar, the Board
  card button and the quick view. The By hand checklist lists batches with a model still waiting
  first and counts only sends that were not stopped.
- Rig doctor, on a robed humanoid: a blended robe is no longer flagged past the body, and a torn
  robe still is. Read from the wraith, past body went from 37.6 and 190.8 mm (flagged) to 0.0 and
  45.2 mm (look here) on a raise and a cast.
- Rig doctor, on a quadruped: the void hound reads 4 legs and 1 tail (it read 5 and 2), with the
  whole head bending, and a fix that moves nothing says so instead of using a round.
- Pin the feet no longer slides more and sticks: the foot rises with the clip on its way back, and a
  pin that still slides more comes off in a third run. The review gives both numbers and the bake
  does not save the pin.
- Real size shrinking a model no longer counts as lost surface, and the thin parts limit for a pack
  warning went from 6 to 12 percent, measured on 14 real Tripo props.
- A re-texture that loses parts now warns in the Inbox and points at Bake back. The copy no longer
  promises that parts survive, and the PBR check is worded per provider.
- The sidebar Inbox always shows the list, not an old rig doctor page.
- The Layout and Paths tabs load models 3 at a time instead of all at once, so the tabs stay
  clickable on a heavy project.
- A disabled segment is dimmed and marked with a lock.
- A game's own files and folders stay when a template is applied.

## Performance

- **No command runs on the main thread any more.** Clicking Settings hung on a Keychain read and
  clicking a template hung on a macOS privacy prompt for Documents, and the whole app stopped,
  native menu included. Keychain and linked folder commands now run on the blocking pool and the
  other 101 commands are async. A new `commands-off-main-thread` lint rule fails on any plain
  sync command. Settings opens at once and a key row says it waits for the Keychain. Commands that
  ran one at a time can now overlap, so `maquette.json`, `layout.json`, `pipeline.json`, the Ship
  settings and the inbox kinds and aims are written under locks, and saving the layout over an
  unreadable `layout.json` is refused. Other files were not re-checked for overlapping writers.
- The Layout and Paths tabs on 66 models, in headless Chromium with software GL and a loaded
  machine: a click on Parts took effect in 0.9 s instead of 13.4 s on Layout and 2.0 s instead of
  7.4 s on Paths. These are rough, single runs and not the real GPU.
- View reads no longer block the window. They ran on the app's main thread, which Tauri uses for a
  plain command, and now run on a blocking thread. For scale, measured in `maquette-core`, the
  look-alike read of 432 library entries takes 14.4 s in a debug build (`tauri dev`) and 0.79 s in a
  release build. These are timings of the work, not of the freeze, which I saw in the desktop app.
- A loader shows at once while a view, its data or its model loads. In headless Chromium in mock
  mode a first open shows a loader from about 25 to 45 ms where it used to stay blank for about 320
  ms.

## Accessibility

- `pnpm a11y` runs 34 cases with 0 failing. The one serious finding, a scrolling column with
  nothing to focus, is fixed. Moderate and minor findings remain (landmarks on a card menu, no `h1`
  on Timeline, a dialog role on three forms).

## Under the hood

- **Rig doctor numbers.** Stretch is the largest change in length of any single edge, and any rig
  stretches an edge across a bent joint, so a new number, stretch past the body, subtracts what the
  mesh does with every vertex stuck to its nearest bone and what a fair skin of the model's own
  weights explains, and is the stretch that 0.5 percent of the surface reaches. Rows are judged by
  that (from 80 mm) and by seam gap (from 5 mm). Seam gap used to be the distance from the mean, which is half the real
  opening; it is now the true gap, so seam gap values read about double compared with before.
  Creature numbers scale to the model's size. The sheets show one verdict per row, bigger cells that
  enlarge on a click, and the pose named on each tile.
- **MCP tools** went from 97 to 118. A check in `lint-meta` fails when a page states a tool count
  that is not the real one, and the MCP tools page has a group index.
- **Site screens.** `pnpm --filter @maquette/site screens` retakes the app screens from mock mode.
- Test scripts and the visual check groups follow the new Board header, and a visual group covers
  the rig doctor.

## Known limits

I want this to be clear about what has and has not been run for real.

**Run by hand in the desktop app:**

- Rig doctor on a humanoid, from the read through to landing it as a new version. The later
  readings were checked against two real files (a robed wraith and a void hound) in headless
  Blender and mock mode, not through the app.
- Export pack, partly: one run stopped at 8 of 431 models, before the later fixes in this release.

**Everything else** was checked by automated tests, by real headless Blender runs where Blender is
involved, and in mock mode. It has not been used by hand in the desktop app. That includes the 3D
quick view, inbox triage, library at scale, render styles, the timeline and page additions, draw on
surfaces, version compare, retarget helpers, game templates and the new Board header.

Known gaps:

- **Meshy re-texture has never run against real Meshy.** Whether the parts stay separate through a
  re-texture is unknown, so look at the parts when the result arrives. Its price of 10 credits comes
  from the example in Meshy's API docs, not from a real call.
- **Render style on a site is only a CSS filter,** an approximation of the Blender look, not a
  render.
- **The 80 mm past body limit comes from test models.** I have not measured it on a wide range of
  real characters.
- **Old rig doctor cases keep their old numbers** until you run them again. Seam gap values read
  about double compared with before because the old number was half the real gap.
- Camera stops in a render and the off screen check (which only sees stops with a hand set model
  list) have only been seen in mock mode.
- **Unsigned builds.** A first install shows Gatekeeper's Open Anyway or SmartScreen's Run anyway.
- **macOS Keychain prompts** for each stored key after each update. Choose Always Allow; macOS may
  ask for your password.
- **A second rig doctor round that moves nothing** still removes the first round's draft, because
  the fix overwrites it. I read this from the code and it should be rare.
- **A tear smaller than 0.5 percent of a model's surface** reads as look here, not bad, however
  long its edges.
- **The wraith's knee step stays in the model.** The rig doctor only points at it.
- **Not run:** Windows, and the first run flows on a clean machine, including a real Keychain
  prompt and a Documents prompt with the app open.
- Avatar is unchanged in this release and is still in early stages.

## Install

Download the `.dmg` (macOS, Apple silicon) or the `-setup.exe` (Windows x64) below, or update from
the app. The builds are not signed by Apple or Microsoft yet, so a first install shows Gatekeeper's
"Open Anyway" or SmartScreen's "Run anyway" once. Install guide:
https://shironex.github.io/maquette/docs/start/install/
