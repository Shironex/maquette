# v0.4.0: Avatar view and VRM 1.0 export

The third update after the public release. It adds an Avatar view that turns a rigged character
into a VRM 1.0 file, with a preview of what it wrote, plus agent skills for Claude Code and Codex,
and discarding and bulk adding in the inbox. The avatar feature is in early stages: it is
recommended for prototyping and playing around, not for production yet. Generated rigs vary, every
step waits for your approval, and you should check the result in Preview before you use it. It is
still early overall: back up your workspace before you update.

## Highlights

- **Avatar view:** check how ready a rigged model is for VRM 1.0, fix its rest pose, and write a
  `.vrm` next to a report, with a Preview of the written file.
- **Every change to the model waits for you:** freeing cloth and hair from the arms, the rest pose
  and the spring chains each show before and after sheets and need a yes in the app. No MCP tool
  approves.
- **Spring bones** for hair, cloth and small charms, found on generated characters that arrive with
  a humanoid rig only.
- **Agent skills for Claude Code and Codex** that teach the Maquette workflows end to end.
- **Inbox:** discard models without deleting them, and add many assets to the library in one call.
- **MCP tools from 92 to 97.**

## What's new

### Avatar view (early stages)

This is the first release of the Avatar view and it is meant for prototyping and playing around,
not for production. Generated rigs vary a lot, so every step that changes the model waits for a
person to approve it, and the written file should be checked in Preview first. Known limits:

- No face expressions and no look at yet. Both are planned for a later release.
- Fused fingers only straighten partly.
- Faces fused between an arm and the body are hidden, not fixed.
- It was tested on a few generated characters, not on a wide range.
- VRM 1.0 only. There is no 0.x export.

**Readiness.** Maquette reads how ready a rigged model is for VRM 1.0 without writing anything. It
maps the 55 VRM humanoid bones (15 required) from VRM, Mixamo, Unreal and Tripo names, and from
descriptive names such as "Left elbow" or "Upper arm L". The Bone map shows which convention won,
where each joint came from and lets you assign bones by hand when the names are unclear. Findings
come ranked as blockers, warnings and notes, and none are dropped. Facing, arm angle, ground, node
scale, hips centre and symmetry are measured, and the inbox checks and the Motion rig check show a
VRM line. Tripo rigs can also be made with VRM bone names (a v3 rig model is needed).

**Export.** The Export tab holds the meta and licence form (filled from defaults you set in
Settings), the bone map, the PBR or MToon soft material switch and the result with Reveal and Copy
path. A model version picker marks the version that waits for you, so an agent's build on an older
version can still be approved. The written file holds `VRMC_vrm` with the humanoid bones, no
animations (VRM ships motion as separate files) and the model's version is never changed. Per
asset settings live in `avatar.json` and survive removing and restoring the asset.

**Three approval steps.** Each runs headless in Blender on a copy, shows before and after sheets
and waits for your yes. A result that changed since you approved it is refused.

- **Free cloth and hair from the arms.** Cloth and hair that a generated rig weighted to the arm
  bones would lift with the arms. This step keeps sleeves, gloves, cuffs and fingers on the arm and
  moves the rest to the spine, chest and shoulder, with a smooth band so sewn cloth stretches
  instead of tearing. The hand is found by its surface, so hair beside a hand is not pinned to it.
  Faces the mesh fuses between a sleeve and the body far from the shoulder would stretch into dark
  strands, so they are hidden by default (or kept, your choice). Hidden faces are tiny and are
  named on the card and in the report.
- **Rest pose.** The model is turned to face +Z, the hips are centred, the soles go on the ground
  and the arms are lifted level as a T-pose, with the elbows straightened by default.
- **Fingers.** Curled fingers are straightened in the palm plane, by as much as the skin allows
  (100, 75, 50 or 25 percent per hand), or kept as they are. Where an auto rig bunched the finger
  joints at the wrist, the hand's joints are repaired first when five fingers can be told apart.

**Spring bones.** Maquette suggests parts that hang off the body, such as a ponytail, a cape or
earrings, each with a kind, root bone, confidence and a colour on a candidates sheet. Small charms
close to the body (belt and jacket charms, short chains) are found too. Nothing is applied until
you confirm the parts you want in the Springs tab, then "Make chains" adds joints along each part
and waits for your yes with a sway test sheet. The file gets `VRMC_springBone` with colliders
measured from the body and presets for hair, cloth and accessories. Picks you made are kept across
model changes when one candidate clearly matches the old one, and a build stops with a clear
message when none does.

**Softer baked highlights.** Generated characters have their lighting painted into the base colour,
which MToon turns into white blotches on dark materials. With MToon, a copy of each base colour
image tones down only strong highlights on dark material, the original stays in the file, and
`highlights` can be set to `keep`. A texture with almost no highlights is left alone.

**Preview and checks.** The Preview tab loads the written `.vrm` the way a VRM app does, with arms
down or T-pose, a breathing idle, a Wiggle button for the springs and chips for the spec, bones,
spring bones and expressions. Every build writes `<asset>.vrm.report.json` with the readiness
before and after, the bone map, what is still unresolved and a round trip, where the written bytes
are read back and `VRMC_vrm`, the required bones, the springs and the textures are checked. A
failure shows up as a blocker.

**Agents.** `get_avatar`, `set_avatar` and `build_avatar` read the avatar, set its meta, bones,
material, highlights, bridges and springs, and build it. A build waits in the app for approval and
sees `denied` if you deny. A new `maquette-avatar-vrm` skill covers the workflow.

### Agent skills for Claude Code and Codex

A plugin in this repo ships four skills: `maquette-lab-round`, `maquette-by-hand-round`,
`maquette-character-rig` and `maquette-game-export`. The Avatar view added a fifth,
`maquette-avatar-vrm`.
`/plugin marketplace add Shironex/maquette` installs them in Claude Code, and `install-codex.mjs`
links them for Codex. Each skill has an example prompt and lists what the app asks you to approve.
A check keeps every tool a skill names in step with the MCP tool list.

### Inbox

A Discard button (after a confirm) and `discard_inbox_model` move a model into `inbox/.discarded`
in the workspace instead of deleting it. A send still waiting for that model is closed as
cancelled and the asset's earlier versions stay. `add_many_to_library` adds many assets in one
call, where a dogfood round had added 121 one call at a time. `get_inbox_checks` now checks a sent
model against its send the same way `list_inbox` does, so both give the same warnings.

## Bug fixes

- The Avatar view opens on the version that waits for approval, so an agent's pending rest pose can
  be reached from the floating card.
- A failed avatar step reports its own name and the script's last error line instead of
  "Animation clips failed".
- `set_avatar` with no springs now means an explicit choice, and a build that would drop the last
  export's springs stops instead of writing a VRM without them.
- A ponytail weighted to the arm by the rig is found as hair from the head, not as cloth from the
  chest.
- The fix-ups preview numbers table no longer clips in the narrow side panel, the Rotate fields sit
  in a grid and the waiting chips line up.
- The third pipeline stage is called "3D model" instead of "Tripo", because Meshy and by hand sends
  land there too.

## Under the hood

- `maquette-core` is split into `maquette-base`, `maquette-glb`, `maquette-preview`,
  `maquette-model` and `maquette-providers`, with a declared layer map that the module graph is
  checked against, and the providers reach the pipeline and inbox through ports.
- The 14 MCP integration test files are one test binary, which removed 654 lines of copies. The
  MCP tool names come from the router into `tool-names.txt`, which the handshake test, the skills
  check and CI read, and a lint rule fails when the README or the site's tool page misses a tool.
- The landing page reads its download version from `tauri.conf.json` and has a section with the
  real compression numbers.

## Dependencies

- The updater's `zip` feature is off, which removes `zip` 4.6.1 (a critical alert) from the
  dependency tree.
- `@pixiv/three-vrm` 3.5.5 loads the Preview in its own lazy chunk (34.5 kB gzip) that loads with
  the Preview tab, so the main bundle is unchanged.

## Install

Download the `.dmg` (macOS, Apple silicon) or the `-setup.exe` (Windows x64) below, or update from
the app. The builds are not signed by Apple or Microsoft yet, so a first install shows Gatekeeper's
"Open Anyway" or SmartScreen's "Run anyway" once. Install guide:
https://shironex.github.io/maquette/docs/start/install/
