# v0.1.0: the first public release

Maquette is a desktop studio I built to take one asset from a concept image to a small, compressed
model in a website or game repo. This is the first release I am putting out in public. I have used
it on real projects for a while (a listening corner of ten props went from 27.4 MB of source models
to 0.89 MB on the page), but it is still early: expect breaking changes and bugs, and back up your
workspace before you update.

## Highlights

- **One Board per project**, from concept to ship, with every asset's picture, version, triangles,
  size and state.
- **A concept Lab** on the Codex CLI: directions with prompts and reference images, stars, picks and
  object refs.
- **3D through Tripo or Meshy**, over their API with an approval for every credit, or By hand on
  their site with the export picked up from your Downloads.
- **An Inbox that checks every model** against the budgets, with fix-ups as buttons.
- **A cached pipeline in headless Blender**: build, bake, export, compress (meshopt and KTX2),
  posters and ship.
- **See what ships before it ships**: the Inspector, the Page view on the site's own dev server,
  Motion and the scroll Timeline.
- **A Library** of finished models reused across projects without spending credits.
- **An MCP server** so Claude Code or Codex can drive all of it, with shipping and paid sends waiting
  for your approval.

## What's new

### Board and projects

Website projects (Floating diorama, Room, Character showcase templates) and game projects imported
from the models a game already has. Cards can be renamed, copied to another project, sent to 3D in a
batch or moved to the workspace trash and restored.

### Lab

Each image is one Codex job, a few run at a time, and a rate limited job runs again on its own. A
concept can be cut into one isolated image per object, and picks go into the project's refs as
assets.

### Send to 3D

Tripo and Meshy over their API, each send approved in the app first, with a credits ledger for API
and subscription spend. By hand writes a handoff folder with the image, the settings and the export
name to use; the Downloads watcher brings the model into the Inbox.

### Inbox and fix-ups

Checks for triangles, texture sizes, PBR maps, rigs, origin and merged meshes, with a shaded,
wireframe, UV checker and skeleton preview. Real size and fix-ups (decimate, shrink textures, merge,
apply transforms, remove loose parts, origin to bottom centre) apply headless on a copy of every
version.

### Pipeline

Steps live in `pipeline.json`, unchanged steps come from the cache, and Blender always runs
headless. Per model compression presets show what each model ships at, starter scripts are kept up
to date, and the site's dev server can be started and stopped from the Pipeline view, the status
bar and the Page view.

### Inspector, Page, Motion and Timeline

Compare two versions of the scene with a slider, fly between camera stops, and read triangles,
textures, GPU memory and transfer per model. The Page view reads frame time and draw calls from the
real page. Motion checks rigs and plays clips; the Timeline keys camera stops, object states,
explode tracks and lit paths to the scroll.

### Ship

A website gets its models, layout and scene data, either as Maquette's whole scene or as models
dropped into a hand-built site, with a size report and a plan of what is written or held back. A
game gets plain `.glb` or `.obj` files at their paths. Ship only replaces files it wrote and never
commits.

### Library

Finished models live outside every project with their versions, tags and refs. Using one copies it
in; a project with an older copy is offered the update.

### Agents

A local MCP server (off by default, `127.0.0.1` only, bearer token) with tools for every view. The
agent rules hold by construction: no screen capture tool, Blender never opens a window, and Ship and
paid sends wait for Approve in the app.

### Settings and updates

Settings > About shows the version, commit and build date. The app checks this repository's
releases and installs updates signed with its own key.

## Under the hood

- Tauri 2 with a Rust core (`maquette-core`), React and three.js in the web view, typed IPC bindings
  generated from Rust.
- Every external program is spawned with an args array, never through a shell.
- CI runs the lint, typecheck, web tests, site build and the Rust tests on macOS and Windows.
  Releases are built, signed and verified by a workflow on the version tag.

## Install

Download the `.dmg` (macOS, Apple silicon) or the `-setup.exe` (Windows x64) below. The builds are
not signed by Apple or Microsoft yet, so the first launch shows Gatekeeper's "Open Anyway" or
SmartScreen's "Run anyway" once; updates through the app do not. The pipeline needs Blender, and the
docs list the other tools: https://shironex.github.io/maquette/docs/start/install/
