# v0.7.1: A provider job fix, clearer approval cards and a self-updating download card

A small patch after v0.7.0. It fixes a write ordering bug in the provider jobs, keeps the floating
approval cards off the buttons they used to cover, and tidies a few rough edges from the v0.7 list.
It also stops writing the `avatarRigTools` setting, which the v0.7.0 notes said would go on for one
release. Read the Heads up section if you share a workspace with a computer on v0.6. This was tried
with automated tests, mock mode and visual checks per change. It is still early: back up your
workspace before you update.

## Heads up

The v0.7.0 notes promised one release of still writing the old `avatarRigTools` switch beside
`toolGroupsOff`, so a computer on v0.6 that shares the workspace over Syncthing would keep the
setting. This release stops writing it. A v0.6 machine that syncs a workspace saved by v0.7.1 no
longer sees that switch, so it will treat the avatar and rig tools as on. Update that machine too,
or leave the workspace to one version.

Nothing changes for a workspace saved by an older version. Reading an older `maquette.json` still
folds a saved `avatarRigTools: false` (with no `toolGroupsOff`) into the avatar-rig group being off,
so nobody gets the avatar and rig tools back on after updating.

## Bug fixes

- **Provider jobs write first, then show.** A job's change was set in memory, the lock was released,
  and only then was `providers.json` written. In that gap a reader could already see the new state
  (Inbox) while the file still said Running, and a restart or a second open at the wrong moment
  resumed a job that had finished. Every change now keeps the lock through the write, so a state
  that can be read is already on disk (#138).
- **Floating approval cards no longer cover buttons.** In the real app the Rig doctor's "Add as v2"
  could sit under its own approval cards, and the only way out was to Deny them. The open case's own
  approval now leaves the floating stack, and the cards and notices lift above any bottom button
  bar. Sheets got a footer slot for this, which also fixes Inbox "Accept into project" and the
  camera panel's "Apply to layout.json" (#140).
- **Success answers skip tools of an off group.** The `next` list in an MCP success answer no longer
  suggests a tool you switched off in Settings > Agents.
- **Plain proposal wording.** A camera plan proposal says "moved from stop N" or "still stop N"
  instead of the old phrasing.
- **Balanced settings columns.** The two columns in Settings follow the nav's order and stay even.

## Under the hood

- The overlap check test counts the work it does (words kept, cards walked, pairs looked at) instead
  of timing it, so it no longer fails on a slow machine and still catches a lost cap (#138).
- The job save tests time out their waits instead of hanging the run.
- **The site's download card updates itself.** The version, date and installer sizes now come from
  the latest GitHub release at build time, and the release workflow redeploys the site after it
  publishes. The checked-in `release.json` stays as the offline fallback (#137).
- The older README images are retaken with the neutral sample names, including the sample inside
  the framed site.

## Known limits

- The approval card change was checked in the browser mock, not yet in the Tauri app. The first real
  release is also the first time the site's download card updates by itself.
- Windows and a second computer on v0.6 reading a workspace saved by this version were not run by
  hand.
- A known mock-only bug is left alone: Deny on a rig doctor card in mock mode says "no longer
  waiting".
- Unsigned builds still show Gatekeeper's Open Anyway or SmartScreen's Run anyway on a first
  install, and macOS asks about the Keychain for each stored key after an update.

## Install

Download the `.dmg` (macOS, Apple silicon) or the `-setup.exe` (Windows x64) below, or update from
the app. The builds are not signed by Apple or Microsoft yet, so a first install shows Gatekeeper's
"Open Anyway" or SmartScreen's "Run anyway" once. Install guide:
https://shironex.github.io/maquette/docs/start/install/
